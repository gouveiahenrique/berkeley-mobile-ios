# Code Conventions

## Naming Conventions

- **`BM` prefix**: 20 files matching `BM*.swift` were found (e.g. `BMConstants.swift`, `BMAlert.swift`, `BMNetworkingManager.swift`, `BMEventCalendarEntry.swift`, `BMColor` referenced throughout). The observed implementation uses this prefix for shared/cross-feature model, constant, and manager types, distinguishing them from feature-scoped types (which do not carry the prefix, e.g. `MapViewController`, `HomeViewModel`).
- **`View` suffix**: 58 files matching `*View.swift` were found. SwiftUI view structs observed in this session declare conformance as `struct X: View { ... }` (47 files contain the literal `: View {` pattern), e.g. `TodayView`, `SafetyView`, `ResourcesView`, `EventDetailView`.
- **`ViewModel` suffix**: 13 files matching `*ViewModel.swift` were found (e.g. `HomeViewModel.swift`, `EventsViewModel.swift`, `SafetyViewModel.swift`, `ResourcesViewModel.swift`, `GymOccupancyViewModel`, `DebugViewModel.swift`). All view models observed are registered in `berkeley-mobile/BerkeleyMobile+Injection.swift` as `Factory<T>` properties on `Container`.
- **`ViewController` suffix**: 6 files matching `*ViewController.swift` were found (e.g. `MapViewController.swift`, `DrawerViewController.swift`, `MainContainerViewController.swift`), used for UIKit `UIViewController` subclasses.
- **Extension-per-file with `Type+Concern.swift` naming**: extensions are split into dedicated files named `<Type>+<Concern>.swift`, e.g. `AppDelegate+Migration.swift`, `TimeInterval+Ext.swift`, `Logger+Ext.swift`, `UIScrollView+GestureRecognizer.swift`, and the `Assets/Colors/Colors+<Feature>.swift` family (`Colors+Text.swift`, `Colors+MapMarker.swift`, `Colors+Calendar.swift`, `Colors+TagView.swift`, `Colors+GymClass.swift`, `Colors+ActionButton.swift`, `Colors+AlertView.swift`, `Colors+StudyPact.swift`, `Colors+Event.swift`, `Colors+Resource.swift`).
- **`UserDefaultsKeys` enum** (`berkeley-mobile/Utils/UserDefaults+Extension.swift`): `UserDefaults` access is not done via raw string literals at call sites; the repository implements a typed enum (`numAppLaunchForFeedbackForm`, `numAppLaunchForAppStoreReview`, `academicEventsLastSavedDate`, `campuswideEventsLastSavedDate`, `recentSearches`, `homeDrawerPinnedItemIDs`) with generic `set<T>(_:forKey: UserDefaultsKeys)`, `integer(forKey:)`, `data(forKey:)`, and `increment(forKey:)` wrapper methods over the standard `UserDefaults` API.

## Architectural Patterns

- **Protocol-oriented shared behavior**: cross-cutting model capabilities are expressed as protocols with default implementations in extensions, under `berkeley-mobile/Data/ItemProtocols/`:
  - `BMCalendarEvent` (`BMCalendarEvent.swift`) — provides a default computed `dateString` formatting implementation.
  - `CanFavorite` (`CanFavorite.swift`) — a single `isFavorited: Bool` requirement.
  - `HasImage` (`HasImage.swift`) — default `image` getter and `fetchImage(completion:)` built on the shared `ImageLoader.shared` singleton.
  - `HasLocation` (`HasLocation.swift`) — location-related fields.
  - Model types compose several of these protocols, e.g. `BMEventCalendarEntry: NSObject, NSCoding, Identifiable, BMCalendarEvent, HasImage, CanFavorite` (`Events/EventDataSource/BMEventCalendarEntry.swift:11`).
- **Dependency injection via Factory**: `berkeley-mobile/BerkeleyMobile+Injection.swift` centralizes all `Factory<T>` registrations on `Container` (from the `FactoryKit` SwiftPM package). View models are injected into UIKit view controllers via `Container.shared.<property>.resolve()` (e.g. `MapViewController.swift:80-81`) and into SwiftUI/UIKit types via the `@Injected(\.propertyName)` property wrapper (e.g. `TabBarController.swift:15`, `@Injected(\.feedbackFormPresenter)`).
- **Delegate-protocol UI composition**: UIKit interactions are wired through Swift protocols with a `Delegate` suffix, e.g. `FeedbackFormPresenterDelegate` (`TabBarController.swift:76-82`), `MapMarkerDetailViewDelegate` (`MapMarkerDetailView.swift:18`), `SearchResultsViewDelegate`, `DrawerViewDelegate`/`MainDrawerViewDelegate`/`SearchDrawerViewDelegate` (`berkeley-mobile/Drawer/`).
- **Drawer framework via protocol extensions**: `berkeley-mobile/Drawer/DrawerViewDelegate.swift` defines the `DrawerState` enum and `DrawerViewDelegate` protocol, with default gesture-handling and animation logic (`moveDrawer`, `handlePan`, `computePosition`) implemented in a `where Self: UIViewController` protocol extension, rather than in a base class. `MainDrawerViewDelegate` (`Drawer/MainDrawerViewDelegate.swift`) extends this pattern for stacked drawers (`dismissTop`, `coverTop`, `hideTop`/`showTop`).
- **Singleton managers**: several cross-cutting services are implemented as singletons with a `static let shared` (or `static var shared`) instance: `DataManager.shared` (`Data/DataManager.swift:21`), `BMNetworkingManager.shared` (`Data/BMNetworkingManager.swift:13`), `ImageLoader.shared` (`Common/Images/ImageLoader.swift:14`), `EventsDataService.shared` (`Events/EventDataSource/EventsViewModel.swift:36`), `BMLocationManager.shared` (referenced in `AppDelegate.swift:25`).
- **`@Observable` SwiftUI view models**: newer view models use the Swift Observation framework's `@Observable` macro combined with `@MainActor`, e.g. `EventsViewModel` (`EventsViewModel.swift:76-78`: `@MainActor @Observable class EventsViewModel`). Not found in codebase within files inspected this session: any view model still using the older `ObservableObject`/`@Published` pattern — all view models found in this session's search used `@Observable`, though this was not an exhaustive search of all 13 `*ViewModel.swift` files.
- **Async/await for network calls**: newer data-fetching code uses Swift concurrency (`async throws`, `Task { ... }`), e.g. `BMNetworkingManager.fetchSafetyLogs()`, `EventsDataService.fetchEventsGroupedByDate()`, `EventsViewModel.init()`. Older data-fetching code (`DataManager.fetch(source:_:)`, `DataSource.fetchItems(_:)`) uses completion-handler closures and `DispatchGroup`/`DispatchQueue`. Both patterns coexist in the repository as of this analysis.

## Documentation Style

- Doc comments use triple-slash (`///`) Swift documentation comment syntax on protocol requirements and public methods, e.g. `Data/ItemProtocols/BMCalendarEvent.swift:15-33`, `Drawer/DrawerViewDelegate.swift:23,26-31`, `AppDelegate+Migration.swift:47,80-83`.
- File headers follow the standard Xcode template: filename, project name, author, and copyright line, e.g. every inspected file begins with a `//  <Filename>.swift` / `//  <project>` / `//  Created by <author> on <date>.` / `//  Copyright © <year> ASUC OCTO. All rights reserved.` block. Some files retain an older `bm-persona` project name and `RJ Pimentel`/`Kevin Hu` authorship in this header (e.g. `AppDelegate.swift`, `SceneDelegate.swift`, `DataManager.swift`), reflecting the repository's history — general convention, header content is not verified as currently accurate metadata.
- `// MARK: -` section comments are used pervasively to divide files into logical sections (e.g. `AppDelegate.swift:37,54,74`, `MapViewController.swift:309,339,408,423`).
