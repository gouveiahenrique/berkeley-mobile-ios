## `berkeley-mobile/` Module Breakdown

Each subdirectory groups a feature area or a horizontal concern. Responsibilities below are drawn from the file names and source content observed via CodeGraph and directory listing.

| Folder | Responsibility (evidence) |
|---|---|
| `AppDelegate.swift`, `SceneDelegate.swift`, `AppDelegate+Migration.swift` | Application/scene lifecycle entry points. `AppDelegate.swift` configures Firebase, kicks off `DataManager.shared.fetchAll()`, and registers push notifications. |
| `TabBarController.swift` | Root `UITabBarController` wiring the four main tabs (Home/map, Today, Safety, Resources). |
| `MainContainerViewController.swift` | Container view controller referenced by `TabBarController` and `MapViewController` (per CodeGraph blast-radius data); hosts the map + drawer flow. |
| `BerkeleyMobile+Injection.swift` | Registers app ViewModels into a `FactoryKit` `Container` (dependency injection). |
| `Data/` | Cross-feature data layer: `DataManager` (fetch orchestration/cache), `BMNetworkingManager` (Firestore queries), `BMLocationManager` (CoreLocation wrapper), `BMEventManager`, `BMConstants`, `BMError`, `DataSource` protocol, and `ItemProtocols/` (shared model protocols: `HasImage`, `HasLocation`, `HasName`, `HasOpenClosedStatus`, `HasOpenTimes`, `HasPhoneNumber`, `HasWebsite`, `SearchItem`, `CanFavorite`, `BMCalendarEvent`) plus `PropertyWrappers/Display.swift`. |
| `Home/` | The map-centric home tab: `HomeView.swift`/`HomeViewModel.swift`, and feature subfolders `Map/` (map view controller, data source, markers, search), `Fitness/` (gyms, gym classes, gym occupancy), `Libraries/`, `Dining/`, `Guides/`, `Search/`, and `Home Drawer/` (drawer-based section list UI). |
| `Events/` | Academic calendar and campus-wide events UI (`EventsView.swift`, `CalendarView.swift`, `EventDetailView.swift`) and `EventDataSource/` (`EventsViewModel.swift` with `EventsDataService`, `BMEventCalendarEntry.swift` implementing `NSCoding`/`BMCalendarEvent`). |
| `Safety/` | Crime/safety log feature: `SafetyViewModel.swift` (Firestore-backed `BMSafetyLog` model and filter state), map view, filter UI, detail view. |
| `Today/` | "Today" tab composed of a custom tile layout (`TodayTileLayout.swift`, `TodayTileAttributes.swift`) and `Tiles/` subfolders per widget-like tile (`Weather Tile/`, `News Tile/`), each with its own ViewModel. |
| `Resources/` | Campus resources tab (`ResourcesView.swift`, `ResourcesViewModel.swift`, `ResourcesSectionDropdown.swift`, `SafariWebView.swift`). |
| `FeedbackForm/` | In-app feedback form presentation (`FeedbackFormPresenter.swift`, `FeedbackFormView.swift`, `FeedbackFormViewModel.swift`); presented from `TabBarController` via `FeedbackFormPresenterDelegate`. |
| `Drawer/` | Reusable bottom-drawer UI system: `DrawerViewController`, `DrawerViewDelegate` (protocol + default pan-gesture handling), `MainDrawerViewDelegate` (drawer-stack management). |
| `Common/` | Shared UI components used across features: `CardView`, `CollapsibleCardView`, `TagView`, `BMAlert`, `BMActionButton`/`ActionButton`, `BMFilterButton`, `BMSegmentedControlView`, `BMCachedAsyncImageView`, `BMContentUnavailableView`, `BMTopBlobView`, `IconPairView`, `ScrollingStackView`, plus `DetailView/` (detail card subviews), `FilterView/`, and `Images/` (`ImageLoader.swift`, `ImageViewCell.swift`). |

| `Utils/` | Type extensions and small utilities: `Date+Extension`, `String+Extension`, `CLLocation+Extension`, `UIView(Controller)+Extensions`, `AtomicDictionary`, `WeeklyHours`, `DayOfWeek`, `Logger+Ext`, etc. |
| `Assets/` | Non-image design tokens in code: `Colors/` (`Colors.swift` plus per-feature `Colors+*.swift` extensions defining `BMColor` values) and `Fonts.swift` with bundled `.otf` font files under `Fonts/`. |
| `Assets.xcassets/`, `Base.lproj/` | Xcode asset catalog and base localization/storyboard resources. |
| `Info.plist` | App target configuration (permissions usage strings, etc.). |

## Architectural Boundaries and Dependencies

- **Data layer → Feature layer:** Feature ViewModels (e.g. `SafetyViewModel`, `EventsViewModel`, `HomeViewModel`) depend on `Data/` singletons (`BMNetworkingManager.shared`, `DataManager.shared`, `BMLocationManager.shared`) and on per-feature `*DataSource` types conforming to the `DataSource` protocol (`Data/DataSource.swift`). `DataManager` holds a fixed list of `DataSource` types it fetches (`MapDataSource`, `LibraryDataSource`, `GymDataSource`) in `Data/DataManager.swift:12-16`.
- **Dependency injection boundary:** ViewModels are constructed through the `Container` extension in `BerkeleyMobile+Injection.swift` rather than being directly instantiated by their consumers in most observed cases (e.g. `MapViewController.init()` calls `Container.shared.homeViewModel.resolve()`).
- **UIKit/SwiftUI boundary:** `TabBarController` bridges SwiftUI screens into the UIKit tab bar via `UIHostingController`; `MapViewController` is exposed to SwiftUI via `UIViewControllerRepresentable` (`HomeMapView` in `Home/Map/MapViewController.swift`).
- **App target vs. widget extension:** `BerkeleyMobileWidget/` is a separate Xcode target/product (`BerkeleyMobileWidgetExtension`, per `Podfile`) that reuses app-side types (e.g. `GymOccupancyViewModel`, `BMFont`) but ships as an independent process/binary; it declares its own `Firebase/Firestore` pod dependency in `Podfile`.
